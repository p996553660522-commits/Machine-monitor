# Устройство мониторинга ESP32

Исходный файл: [`firmware/MachineMonitor/MachineMonitor.ino`](../firmware/MachineMonitor/MachineMonitor.ino). Версия прошивки — `1.2.2`, HA-интеграции — `1.4.0`. Настраивается адрес MQTT-брокера; сохранено отключение отдельных линий; GPIO, LOW → ON и существующие state topics сохранены.

## Оборудование и сигналы

Текущий стенд: классический ESP32 DevKit / ESP32-WROOM-32, четырёхканальная плата PC817 и преобразователь питания XL4015E.

| Физический вход | GPIO ESP32 | Настройка |
|---|---:|---|
| Input 1 | 32 | INPUT_PULLUP |
| Input 2 | 33 | INPUT_PULLUP |
| Input 3 | 25 | INPUT_PULLUP |
| Input 4 | 26 | INPUT_PULLUP |

На стороне ESP32 выход соответствующего оптоканала должен опускать GPIO к логическому LOW при активном сигнале. LOW → ON; HIGH → OFF. Подавать напряжение машинного сигнала прямо на GPIO нельзя; GPIO рассчитаны на логику 3,3 В. Выходной транзистор оптоканала работает с логической землёй ESP32. Изоляция и подключения входной стороны зависят от конкретной PC817-платы.

В репозитории нет универсальной электросхемы для произвольного оборудования. Проверьте допустимое входное напряжение и резисторы именно вашей платы PC817. Настройте преобразователь на требуемое вашей ESP32-плате питание до подключения; допустимые точки подачи питания зависят от платы. Для цепей сетевого напряжения требуется отдельное проектирование квалифицированным специалистом.

## Сборка Arduino IDE

1. Установите Arduino IDE и поддержку **esp32 by Espressif Systems** через Boards Manager. Официальная инструкция: [Arduino ESP32 Installing](https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html).
2. При необходимости добавьте в настройки Boards Manager URL:

   ```text
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```

3. В Library Manager установите **PubSubClient** (Nick O'Leary). [Исходники библиотеки](https://github.com/knolleary/pubsubclient). WiFi, WebServer, Preferences и ESPmDNS входят в Arduino ESP32 core.
4. Распакуйте всю папку `firmware/MachineMonitor` и откройте `MachineMonitor.ino`. Файл `BrokerAddress.h` должен остаться рядом со скетчем. Имя файла и каталога скетча совпадают.
5. Выберите плату, соответствующую своему ESP32; для обычной DevKit используйте подходящий вариант **ESP32 Dev Module**, и выберите USB/COM port.
6. Адрес брокера теперь задаётся через веб-конфигуратор, редактировать скетч для этого не нужно. Значение по умолчанию `homeassistant.local:1883`; `MQTT_PORT` остаётся 1883. Setup-AP пароль `AP_PASSWORD` фиксирован в исходнике. Замените пароль собственным до эксплуатации; не коммитьте production credentials.
7. Выполните **Verify**, затем **Upload**. Откройте Serial Monitor на **115200 baud**. Если плата требует ручного входа в bootloader, используйте её кнопку BOOT при загрузке.

Прошивка проверена сборкой для `esp32:esp32:esp32` (ESP32 Dev Module), Arduino ESP32 core 3.3.11 и PubSubClient 2.8. Загрузка и проверка на физическом устройстве не выполнялись.

## Первый запуск

Без сохранённой Wi-Fi сети ESP32 создаёт AP `MachineMonitor-<короткий ID>`. Пароль берётся из константы `AP_PASSWORD` вашего скетча.

1. Подключитесь к AP устройства.
2. Откройте адрес из Serial Monitor, обычно **http://192.168.4.1/**.
3. Введите Device name, Wi-Fi SSID/password, MQTT broker address, MQTT username/password.
4. Нажмите **Save and reboot**. Настройки сохраняются в Preferences/NVS; устройство перезапускается примерно через 2 секунды.
5. После подключения к домашней сети настройочная AP отключается. Страница остаётся доступной по IP ESP32 или `http://<hostname>.local/`, если локальная сеть разрешает имя.
6. Проверьте Serial Monitor: Wi-Fi и MQTT connected, публикация Discovery и состояний. Найдите четыре sensor в интеграции MQTT Home Assistant.

Для имени устройства используйте простое имя латиницей, цифры и дефисы. Скетч фильтрует hostname, но напрямую вставляет Device name в HTML и Discovery JSON без escaping; кавычки и HTML-символы могут нарушить страницу или Discovery.

## Что делает скетч

- Debounce физических входов — 50 мс.
- Состояния читаются даже без сети, но события за время отсутствия MQTT не буферизуются.
- Wi-Fi reconnect: попытки каждые 10 секунд; примерно после 20 секунд отсутствия Wi-Fi включается fallback AP, одновременно продолжается поиск сохранённой сети.
- MQTT reconnect: интервал попыток 5 секунд. При соединении публикуются Discovery, availability `online` и текущие состояния включённых линий.
- При HA birth `homeassistant/status = online` повторно публикуются Discovery и текущие состояния.
- Настроечная страница показывает входы и состояние связи; сохранение настроек перезапускает ESP32.
- В этом скетче нет OTA, SD-buffer, исторической догрузки и выходов управления.

## MQTT protocol

`deviceId` формируется из MAC чипа, а не из пользовательского имени. Переименование не меняет этот ID.

| Topic | Payload | Retain |
|---|---|---|
| `machine_monitor/<deviceId>/state/input1` … `input4` | `ON` / `OFF` | Да |
| `machine_monitor/<deviceId>/availability` | `online`; LWT `offline` | Да |
| `machine_monitor/<deviceId>/event` | JSON с `input`, `state`, `millis` | Нет |
| `homeassistant/binary_sensor/<deviceId>/input1/config` … `input4/config` | MQTT Discovery JSON | Да |

Пример event:

```json
{"input":1,"state":"ON","millis":123456}
```

`millis` — время от старта ESP32, не UTC timestamp. HA-интеграция использует source entities и не строит свою историю из этого event topic. Потеря связи означает неизвестную активность: восстановление текущего ON не доказывает непрерывность ON в пропущенном периоде.

Транспорт текущего скетча — обычный MQTT TCP без TLS. Настройочная HTTP-страница не требует авторизации; содержимое password-полей включает сохранённые значения. Развёртывайте устройство в доверенной/изолированной локальной сети; подробности — [ограничения](SECURITY_AND_LIMITATIONS.md).

## Устройство с тремя оптопарами и отключение линий

1. Обновите интеграцию до 1.3.0 и перезапустите Home Assistant, обновите его страницу в браузере.
2. Загрузите прошивку 1.2 на ESP32. Не стирайте NVS без необходимости: Wi-Fi/MQTT настройки сохраняются. При отсутствии новых ключей все четыре линии включены, как раньше.
3. Откройте IP ESP32 или его `http://<hostname>.local/`. В HA MQTT-устройство также получает ссылку **Посетить / Visit** на конфигуратор (если `.local` не разрешается, используйте IP).
4. В **Signal lines / Сигнальные линии** оставьте Input 1–3 включёнными, выключите Input 4. Нажмите **Save and reboot**.
5. При первом добавлении Machine Monitor выберите источники входов 1–3; поле входа 4 можно оставить пустым. Для уже настроенной машины из четырёх входов менять профиль необязательно: отключённая линия распознаётся автоматически.

Выключенный вход остаётся зарегистрированным binary_sensor с прежним unique_id и состоянием `unavailable`. Это намеренное отключение, а не измеренное OFF. Атрибут `acquisition_enabled: false` позволяет Machine Monitor исключить его из проверки связи и semantic priority. На странице Machine Monitor отображается **Отключён**. История закрывается в момент получения изменения в HA; прошлые физические интервалы и статистика сохраняются. Скрытая строка доступна через фильтры Real Flow; фильтр не включает аппаратную линию.

Повторное включение создаёт новый физический ON-интервал только после достоверного ON. Время перезагрузки ESP32 является OFFLINE для оставшихся включённых источников. Если выключить все линии, Machine Monitor показывает OFFLINE с причиной «Нет включённых источников»: состояние машины определить нельзя.

Настройка **Включён** в профиле HA остаётся отдельным пользовательским разрешением. Для наблюдения нужны оба разрешения: профиль и ESP32. Отключённая линия не увеличивает время активности; прошлые данные остаются в выбранном историческом периоде. После дальнейших переключений линий перезапуск HA или reload интеграции не нужен — обновления приходят через существующий событийный механизм.

### Дополнительные MQTT topics версии 1.2

| Topic | Retained payload | Назначение |
|---|---|---|
| `machine_monitor/<deviceId>/config/inputN` | `{"acquisition_enabled":true}` или `false` | JSON-атрибут исходного HA sensor |
| `machine_monitor/<deviceId>/availability/inputN` | `online` / `offline` | Доступность конкретной линии |

Discovery использует оба availability topic (модуль и линия), `availability_mode: all`, а также `json_attributes_topic`. Это стандартные возможности [HA MQTT binary sensor](https://www.home-assistant.io/integrations/binary_sensor.mqtt/). Существующие `state/inputN` с ON/OFF, device ID и Discovery unique_id не изменены. Семантика машины остаётся в HA, в ESP32 добавлено только управление сбором физических входов.

## Исправление первого запуска — firmware 1.2.1

В версии 1.2 сервер HTTP запускался до инициализации Wi-Fi/lwIP. На некоторых ESP32 core это приводило к `assert failed: xQueueSemaphoreTake` сразу после `Inputs initialized`. В 1.2.1 сервер запускается после выбора STA или конфигурационной AP. Перепрошейте устройство; стирать NVS или менять настройки HA не требуется. Первый запуск без сохранённого SSID должен показать STARTING CONFIGURATION AP, адрес AP, Web server started и SYSTEM READY.


## MQTT через VPN и адрес брокера (firmware 1.2.2)

В конфигураторе ESP32 появилось поле **MQTT broker address / Адрес MQTT-брокера**. Для второго завода: `192.168.0.22`. Указывайте только IPv4 или ASCII DNS-имя без `http://`, пути и `:1883`. Порт остаётся 1883. Нажмите **Save and reboot**; адрес сохраняется в Preferences/NVS и переживает отключение питания. Пустое поле возвращает `homeassistant.local`.

IP подключается напрямую, без DNS/mDNS. Это подходит для маршрутизируемых сетей и IPsec при доступном MQTT-порте брокера. Имя `.local` по-прежнему требует разрешения в сети устройства. MQTT username/password должны соответствовать брокеру.

При обновлении устройства со старой прошивкой новый ключ отсутствует: автоматически используется прежний `homeassistant.local`. Сохранённые Wi-Fi/MQTT credentials, имя, флаги линий и аппаратный deviceId сохраняются. Для сохранения NVS используйте прежнюю разметку разделов и **не включайте Erase All Flash**. Прошивка сама не очищает Preferences.

Неверный адрес отклоняется HTTP 400 до записи любых настроек и перезапуска. Старый клиент, не передавший новое поле, сохраняет текущий broker. Проверка DNS принимает только успешный результат и ненулевой IP; код ошибки не превращается в ложный «broker found».

Для установки скачайте [firmware-v1.2.2](https://github.com/p996553660522-commits/Machine-monitor/releases/tag/firmware-v1.2.2), распакуйте firmware ZIP и прошейте через USB. OTA не добавлялась. HA-интеграцию и роутер обновлять не требуется. После загрузки откройте страницу ESP32, заполните поле брокера и проверьте MQTT CONNECTED. При возврате к firmware 1.2.1 новый ключ останется в NVS, но старый код будет использовать свой фиксированный `homeassistant.local`.
