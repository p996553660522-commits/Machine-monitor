# Руководство пользователя Machine Monitor

## Основной экран

**Боковое меню → Machine Monitor** открывает обзор всех машин. Карточка машины показывает состояние, длительность и итоги за сегодня. Можно сортировать машины по названию, состоянию, времени работы/простоя или последней активности. Нажмите машину, чтобы открыть её рабочий экран.

- **Мониторинг / Monitor**: текущий статус, показатели выбранного периода, Real Flow, фильтры, physical totals, semantic statistics и events.
- **Отчёты / Reports**: расчёт периода A и необязательного периода B, сравнение и итоги по сменам.
- **Диагностика / Diagnostics**: размер истории, срок хранения, первая/последняя запись и состояние источников.

## Язык

**⚙ Настройки / Settings → Язык интерфейса**: Русский, English или автоматически по Home Assistant. Ручной выбор сохраняется в localStorage этого браузера и применяется к полному UI, отдельным карточкам и редактору. На другом устройстве настройка независима. Если браузер запрещает storage, выбор действует до закрытия страницы. Смена языка не меняет Machine Profile и названия, введённые пользователем.

Настройки интеграции в HA используют язык профиля Home Assistant; переключатель Machine Monitor относится к её собственному UI.

## Настройка машины

**Настройки → Устройства и службы → Machine Monitor → нужная запись → Настроить**.

Выберите настройки машины или конкретного входа. Для входа задаются источник binary sensor, пользовательское имя, описание, semantic state, приоритет, цвет/иконка, enabled, показ в timeline и участие в статистике. Состав полей определяется текущим Options Flow.

Имена входов хранятся в Machine Profile и поступают в UI через backend API. Не нужно переименовывать диагностические sensors ради изменения Real Flow.

Пример профиля:

| Вход | Имя | Состояние | Приоритет |
|---|---|---|---:|
| input_1 | Нагрев | heating | 60 |
| input_2 | Работа | work | 100 |
| input_3 | Остывание | cooling | 80 |
| input_4 | Поддержание | idle | 10 |

При одновременно включённых нагреве и работе обе физические строки видны, а текущее semantic state — work. Приоритет выбирает состояние машины, а не удаляет остальные сигналы.

В общих настройках можно задать описание, monitoring enabled, состояние при отсутствии активных сигналов, порог длительного простоя, порядок строк, retention и смены. Пользовательский порядок, например `input_3,input_1,input_4,input_2`, сохраняется после валидации. Старый параметр history_limit может присутствовать в конфигурации: основное ограничение истории в текущей версии — retention в днях, а не обрезание до 5000 записей.

## Real Flow

Подробный режим — одна строка на физический вход и единая временная ось. Цвета берутся из профиля. Перекрывающиеся интервалы показывают одновременные сигналы. Компактный режим сохраняет физические интервалы в одной полосе.

Фильтры позволяют показывать любой набор входов; **Все / Ни одного** меняют только отображение, не историю. Сортировка строк: заданный порядок, название, длительность, количество включений, последняя активность.

Выберите период в верхней части экрана: часы, сегодня/вчера, недели/месяцы, последние дни или свой диапазон. Доступны масштаб −/+, перемещение, Сейчас и навигатор времени. Все строки перемещаются вместе. Наведение, нажатие или фокус клавиатуры на интервале показывают имя входа, ON, начало, конец и длительность; открытый интервал имеет конец Сейчас.

OFFLINE отмечается нейтральной штриховкой. Это отсутствие достоверных данных, а не выключенный вход и не простой. Физический ON до обрыва закрывается; подтверждённый ON после восстановления открывает новый интервал.

## Статистика и события

Physical Inputs показывают отдельные длительности ON и количества включений; их сумма может превышать длительность периода при одновременной активности.

Semantic Statistics описывает победившие состояния. Доли productive/non-work рассчитаны по включённому в статистику известному времени. OFFLINE не является WORK или IDLE; его доля рассчитывается от всего выбранного периода. Значение non-productive может включать не только idle, но и другие нерабочие категории согласно профилю.

Events показывает semantic intervals с длительностью и источником. Это не сырая запись всех HA state changes. Можно менять порядок по времени или длительности.

## Отчёты и смены

На вкладке Отчёты выберите местные даты начала/конца периода A. Для сравнения заполните обе даты B. Нажмите **Рассчитать / сравнить**; отчёт не пересчитывается автоматически при каждом live event.

Показатели включают известное время, OFFLINE, отсутствие записей, работу/простой, циклы и длительные простои, semantic categories и physical totals. Циклы считаются по началу работы внутри периода; пересекающий начало периода уже идущий цикл не является новым стартом. Разница долей отображается в процентных пунктах, остальных сравнений — в процентах; при нулевом значении A изменение не определено.

Смены задаются в настройках машины, по одной на строку:

```text
Дневная | 08:00 | 20:00
Ночная | 20:00 | 08:00
```

Используется часовой пояс HA; смены через полночь поддерживаются. В таблице смен отчёта используются данные периода A.

## Хранение истории

**Диагностика → Хранение истории** показывает retention и размер persistent file. Доступны 7, 14, 30, 60, 90, 180, 365 дней; по умолчанию 30. Старые завершённые интервалы удаляются при очистке; открытые и пересекающие границу сохраняются. Уменьшение срока может удалить старые записи; увеличение не восстанавливает удалённые данные.

История хранится в HA `.storage` и переживает перезапуск. Создавайте HA backups с `.storage`. Нельзя удалять эти файлы при обычном обновлении исходников. Время до начала фактического сбора истории неизвестно и не должно восприниматься как простой.

Сервис `machine_monitor.clear_history` удаляет историю. Указанный entry_id ограничивает его одной машиной; пустой entry_id очищает все машины. Это не действие для обновления интеграции или смены профиля.

## Live-обновления

Основной путь — HA event → backend → уведомление frontend с debounce 250 мс. Опрос раз в 5 секунд страхует пропущенные уведомления. Локальный секундный таймер обновляет длительность без запроса всей истории. При ошибке соединения UI сохраняет последние полученные данные и показывает ошибку; они не означают подтверждённое текущее состояние после потери связи.
